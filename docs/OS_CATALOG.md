# Studio Platform OS Catalog

This catalog is the canonical navigation layer for the Studio Platform operating system. It groups documents by the decision or work they govern, rather than by the order in which they were created.

## Strategy and foundations

Use these documents to decide what Studio Platform is, what it sells and how the operating system fits together.

- `strategy/` — positioning, ideal client profile, service architecture, pricing principles, business model, competitive context and brand foundations.
- `framework/STUDIO_PLATFORM_FRAMEWORK.md` — the Understand → Validate → Design → Build → Verify → Launch → Improve delivery model.
- `framework/OPERATING_MANUAL.md` — the integrated operating model.
- `framework/DEFINITION_OF_DONE.md` — minimum conditions for work to be considered complete.
- `framework/CAPABILITY_MAP.md` — evidence-based view of what the studio can reliably sell and deliver.
- `framework/MATURITY_MODEL.md` — progression from founder dependency to a continuously improving system.
- `framework/PROJECT_HARVEST.md` — conversion of completed work into reusable capability.

## Choosing the right document

Use a **gate** when deciding whether work may proceed. Use a **standard** when minimum behaviour must remain consistent. Use a **template** to create a durable record. Use an **ADR or decision record** for a consequential trade-off. Use an **evidence record** when a claim must be tied to a specific version or environment. Use a **harvest** when converting experience into improved capability.
